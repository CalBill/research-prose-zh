# 从优质研报校准语言规则

本流程用于把用户认可的样本转成可复用规则。它是上下文指令与示例的提炼过程，不应描述为已经训练或微调了模型。

## 当前版本依据

用户最新明确将这套表达要求默认用于中文文档的起草、改写和润色，覆盖Word、WPS、飞书等载体及聊天中交付的文档草稿，日常聊天不默认采用。当前不追求完整研报生产能力。以下研报分析仅作为表达参考；扩充研究类型或范文数量不是使用基础规则的前置条件。后续按实际出现的表达问题补充案例。

当前v0.3沿用两篇中信证券公司研究正文的探索分析、用户提供的两个问题片段、三轮起草与改写反馈，并结合后续文档局部修改与用户对累积更新的要求。规则继续保留论证关系、自然搭配、标点和虚词等既有要求，本轮补充研究层次、实际意图和段落收束。编辑自查建议不等同于用户逐项认可。浙版传媒未参与最初规则归纳，后已用于第1轮改写验证，不能继续作为未使用的留出样本。

写出指令文件仅说明已有可试验的载体。三轮稿件及用户反馈不证明跨模型、跨任务的稳定收益。自拟短片段只检查局部规则的执行，不用于证明已达到用户要求的研究报告文风。

用户反馈中已明确的偏好是：泛泛的核验提醒可以直接删除；保留正式语域，改掉生硬句法；句间连续推进，段落充分展开后自然结束。候选的研报共性包括沿业务过程解释、按有意义的维度比较、区分事实与假设。行业和技术研究的覆盖仍需实际任务验证。

本地版本由现有材料与反馈直接整理。writing-dna-skill曾作为相邻方法查阅，未下载或运行，不将本版描述为该项目自动生成的结果。

## 选择样本

先根据用户日常任务确定文体。行业深度、公司深度、宏观评论、业绩点评及投决备忘录可有不同的论证节奏；混合样本时分别标注，避免压成一种平均文风。

建议先用5—10篇高度认可且类型相近的报告试做，这是起步工作量建议，没有保证效果的最低篇数。优先看具体文章、作者及段落，机构声誉只作筛选线索。长报告不必全文同等采样，摘要、核心论证、公司分析及风险段落各有用途。

选择时记录用户喜欢或不喜欢的原因。保留部分完整报告作为后续检验样本，不参与规则提炼；同一篇报告的相邻章节不要拆成提炼样本和检验样本。

## 记录样本证据

每份材料记录标题、作者或机构、日期、文体、文件名、页码或章节定位，以及提取质量。正文、图表注释、模板页眉、法律声明分别识别；跨页、分栏或OCR错误先修正，别把抽取乱码当成句法习惯。

按以下层次观察，围绕能改变写作决策的差异记录，不追求把所有语言指标量化：

| 层次 | 需要回答的问题 |
| --- | --- |
| 研究判断 | 观点放在哪里？怎样表述分歧、归因、推断及预测？ |
| 证据组织 | 数据如何衔接判断？比较基准和传导关系如何展开？ |
| 段落衔接 | 一段承担什么功能？何时换段，何时使用转折？ |
| 语句与术语 | 主体、动词、专业名词、长短句怎样配合？ |
| 边界与风险 | 哪些限定有信息，放在哪里，如何避免重复？ |
| 标题与呈现 | 标题如何表达结论？列表和加粗在何处有用？ |

每条候选规则写明：适用场景、具体动作、样本位置、短例或释义、保留例外。区分“多份样本反复出现”“单篇作者习惯”“用户明确偏好”及“编辑者建议”；不要把建议伪装成观察所得。

同一规则最好有不同报告的支持。只有一份样本时先形成该样本的风格说明，不宣称代表整个研究所；少数样本中的偶然句式不升级为统一规定。

## 形成可执行规则

把“专业、严谨、深刻、凝练”等评价改成可观察的动作，例如：

- 在讨论份额变化时交代分母、时点及口径。
- 预计值与已披露值分开表述，预测条件靠近相应判断。
- 同一段内用证据解释一个主要判断，避免连续列出互不相关的结论。

保留样本支持的灵活性。不要把券商常用词、四字格、被动句或长句一概定为好或坏；不要给句长、段长和连接词数量设置没有实际依据的硬指标。

用新的自拟材料编制改写对照，标明虚构示例。借鉴表达方式及论证组织，不挪用样本中的数据、立场或原句作为新报告的事实。

## 检验规则是否改善正文

从用户的实际任务准备不同输入：证据充分的起草材料、空话较多的初稿、必须保留条件的预测、带不利证据的材料，以及本来就写得好的段落。

对相同材料分别生成基准稿与使用规则的稿件，尽量保持模型、输入与篇幅要求相同。交换展示顺序，先让用户比较，再解释改动。保留检验用报告主要用于评估文体，不把其句子喂给改写任务作答案提示。

评价顺序：

1. 事实、归因、条件与实质信息是否保全；有重大新增或遗漏时先修复。用户已允许删除的通用提醒不按独立事实统计。
2. 核心判断是否明确，证据及关系是否足够支撑。
3. 防御、铺垫、重复是否减少，必要的限定是否仍然准确。
4. 正文是否连贯，是否接近用户认可的正式程度与论证节奏。

允许标注“无明显差异”，也允许原文无需改写。不要把更短、更多强断言或更多术语等同于更好。用实际失败修订对应规则，避免不断增加全局禁令。

## 更新 skill

将常用且经验证的规则放入 SKILL.md；样本证据、文体差异与改写例放入有明确用途的参考文件。更新前后保留可对照版本。阶段说明与实际工作相符，分别记录样本分析、用户反馈、自拟材料检查和真实任务验证，说明覆盖的文体。

### 累积更新，避免矫枉过正

- 默认保留已确认的要求，新反馈只修正对应问题。只有用户明确改变偏好时，才用新要求替代旧要求；遇到实际冲突时指出冲突，不自行认定最新案例推翻此前要求。
- 分别记录用户明确要求、具体文章中的修改和编辑者自查建议。文章中的研究目的、事实或范围修改，不自动升级为语言偏好；未修改的句子也不等于用户明确认可。
- 新规则写出适用条件。某句需要展开先后关系，不意味着禁用“以及”；删去一条多余分支，不意味着删除有用条件；适当增加连接，不意味着所有段落都使用“先、再、最后”。
- 更新后回查已有案例：泛泛核验提醒仍可删除，事实与实质条件仍需保留，转折和解释关系不能改偏，自然搭配与准确术语不为压缩而牺牲，标点和虚词不形成禁词或固定配额。新旧案例不能兼顾时，收窄或撤回新规则。
- 公开规则时使用可公开的材料或标明来源的自拟例子。内部文档原文、链接、评审记录保留在本地，未经明确授权不随Skill更新公开。
